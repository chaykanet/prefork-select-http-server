# HTTP-сервер

## Вариант: 2 prefork и select

Курсовая работа по компьютерным сетям, вариант 2. C++20 и POSIX sockets. Для сборки используется Makefile.

Все команды ниже выполняются из каталога `prefork-select-http-server`.

## Собрать проект

```sh
make build
```

Команда собирает сервер `build/static_server` и тестовый клиент `build/connection_test`. Нужны Clang с поддержкой C++20, make и Python 3.
Первый нагрузочный сценарий также использует установленный `wrk`.

Обычный запуск сервера:

```sh
./build/static_server --root ./public --workers 4
```

После этого страница доступна по адресу http://127.0.0.1:8080/. Остановка — Ctrl+C.

## Проверить корректность

```sh
make test
```

Тест сам запускает сервер во временном каталоге. Проверяет HTTP, безопасность путей, передачу 128 МиБ, несколько клиентов, перезапуск worker и завершение.

## Нагрузочный сценарий 1 — wrk

```sh
make load1
```

Сценарий сам создает файл 16 МиБ, запускает сервер с четырьмя workers на порту 8081 и выполняет `wrk`: 100 соединений, 30 секунд. После теста сервер останавливается, временный файл удаляется.

Результаты сохраняются в новой папке `artifacts/load1_дата_время/`:

- `result.txt` — исходный вывод wrk: запросы в секунду, суммарная скорость, задержки и ошибки;
- `settings.txt` — параметры измерения и сведения о системе;
- `command.txt` — команда измерителя;
- `server.log` — журнал сервера;
- `server-stderr.txt` — ошибки запуска сервера, обычно пустой.

`Requests/sec` — число запросов в секунду, `Transfer/sec` — суммарная скорость. 

Сервер закрывает соединение после ответа, поэтому измерение включает переподключения. Вывод wrk сохраняется без пересчета единиц. Проверяйте ошибки сокетов и ответы не 2xx/3xx: код завершения wrk не гарантирует отсутствие ошибок.

## Нагрузочный сценарий 2 — скорость каждого соединения

```sh
make load2
```

C++-клиент открывает 100 соединений. Каждый клиент работает в отдельном потоке тестового приложения. 
После завершения попыток подключения дается общий старт: каждое соединение запрашивает один файл 16 МиБ. 
Проверяются статус 200 и получение размера тела, указанного в Content-Length.

Результаты сохраняются в `artifacts/load2_дата_время/`. 
Появляются:

- `result.txt` — успешные соединения, ошибки, общая длительность, суммарная, минимальная, медианная и p95 индивидуальных скоростей.
- `connections.csv` — одна строка на соединение: номер, байты тела, время в секундах, скорость в МиБ/с, `ok` или `error`.

Время каждого соединения считается от общего старта до завершения чтения. Скорость в МиБ/с = байты тела / время в секундах / 1048576. Суммарная скорость — сумма байтов успешных ответов / время всего запуска. Ошибочные ответы не входят в статистику успешных скоростей.

Сценарий заканчивается, когда все клиенты завершили запросы. Таймаут сетевых операций клиента — 30 секунд, ограничение всего запуска — 180 секунд. Ошибки приводят к ненулевому коду завершения, результаты сохраняются.

## Изменить нагрузку

```sh
make load1 WORKERS=1 CONNECTIONS=10 SECONDS=10 SIZE_MIB=1
make load2 WORKERS=4 CONNECTIONS=100 SIZE_MIB=128
make load1 PORT=8082
```

| Параметр | Значение по умолчанию | Обозначает |
|---|---:|---|
| WORKERS | 4 | Число процессов сервера |
| CONNECTIONS | 100 | Число клиентов |
| SECONDS | 30 | Продолжительность wrk |
| SIZE_MIB | 16 | Размер файла в МиБ, от 1 до 128 |
| PORT | 8081 | Порт отдельного тестового сервера |

Если порт занят, выберите другой через PORT. Уже работающий сервер сценарии не останавливают. 
Предел клиентов на worker устанавливается равным CONNECTIONS, но не более 900; фактическая вместимость зависит от FD_SETSIZE и лимита ОС (`ulimit -n`). Лимиты ОС скрипт не повышает.

## Построить график

Укажите CSV конкретного запуска:

```sh
python3 scripts/plot.py artifacts/load2_ДАТА_ВРЕМЯ/connections.csv
```

Рядом появится `speeds.svg`. Синие столбцы — успешные ответы, красные — ошибки.

## Модули

- `server/`: конфигурация, listening socket, fork, перезапуск и завершение workers;
- `worker/`: select, прием клиентов, состояние соединения, частичные чтение и отправка, таймауты;
- `http/`: разбор заголовков, статусы и формирование ответа;
- `files/`: декодирование URL, безопасное открытие файлов, MIME;
- `logger/`: общий журнал записи;
- `public/`: статика;
- `tests/`: функциональные проверки;
- `scripts/`: запуск нагрузочных сценариев и построение графика;
- `artifacts/`: результаты нагрузочных запусков;
- `load/`: C++-клиент для измерения скорости каждого соединения.

## Поведение и ограничения

Поддерживаются HTTP/1.0 и HTTP/1.1, GET и HEAD, статусы 200/403/404/405. Некорректные запросы и заголовки больше 16 КиБ получают 400. Для HTTP/1.1 требуется Host. HEAD не содержит тела, включая ответы об ошибках. Для 405 передается `Allow: GET, HEAD`.

Один запрос на TCP-соединение, ответ содержит `Connection: close`. 

`/` соответствует `index.html`. Query-параметры не участвуют в выборе файла. Все компоненты открываются через `openat()` с `O_NOFOLLOW`.

Listening socket и клиентские сокеты неблокирующие. Родитель создаёт workers через fork и не принимает клиентов. Каждый worker обслуживает несколько клиентов через select; перед добавлением сокета проверяется FD_SETSIZE. Файлы передаются порциями до 64 КиБ, без загрузки всего файла в память. Функциональный тест проверяет файл размером ровно 128 * 1024 * 1024 байт.

Журнал содержит время, PID, IP, метод, путь, статус, число отправленных байтов (включая HTTP-заголовки) и причину закрытия. Нулевой статус означает, что ответ еще не был подготовлен. Управляющие символы заменяются, длина записи ограничена. Используются O_APPEND и одна операция write на строку.

Workers наследуют обработчики сигналов. Родитель проверяет их завершение каждые 100 мс и запускает замену. При остановке активные передачи закрываются, родитель ожидает завершения workers.
